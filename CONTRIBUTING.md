# Contributing to LibriMe

Thank you for your interest in contributing to LibriMe. To ensure a productive collaboration and maintain project quality, please adhere to the following guidelines.

## Reporting Issues

If you encounter a bug or have a suggestion for improvement, please open an issue in the repository. Provide a clear description of the problem or feature request. For bug reports, include steps to reproduce the issue, the expected behavior, and information about your environment.

## Pull Request Process

The following steps should be followed when submitting code changes:

1. Fork the repository and create a new branch for your work.
2. Implement your changes while adhering to the project's coding standards.
3. Ensure that your code is well documented and includes relevant tests.
4. Verify that all existing tests pass and the system remains stable.
5. Submit a pull request with a detailed description of the changes and the problem they solve.

All submissions will be reviewed by the maintainers. Feedback may be provided, and changes might be requested before the pull request is merged.

## Development Setup

The project is composed of multiple modules. For local development:

* **Backend**: Refer to the documentation in the `/Backend` directory for Java and Spring Boot setup.
* **AI Module**: Documentation for the Python services is located in the `/AiModule` folder.
* **Frontend**: See the `/frontend` directory for React and TypeScript development instructions.

Refer to the main README for information on the full system orchestration using Docker Compose.

## Coding Standards

* **Consistency**: Maintain the established style and architecture of the respective module.
* **Documentation**: Use meaningful variable names and provide comments for complex logic.
* **Testing**: New features and bug fixes must be accompanied by automated tests.
